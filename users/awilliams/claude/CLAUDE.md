# Global config

## gstack

gstack is built and installed by nix-config, not from a checkout.
`~/.claude/skills/gstack` and every gstack skill directory link into a
read-only Nix store path, for Claude Code, Codex and OpenCode alike.

- Updates arrive through nix-config's package updates. gstack's own update
  check and auto-upgrade are off and `/gstack-upgrade` isn't installed: never
  `git pull`, run `./setup`, or edit files under the install.
- Binaries: `~/.claude/skills/gstack/bin/` (e.g. `gstack-config`). Runtime
  state and `config.yaml` live in `~/.gstack`.
- Upstream source: https://github.com/garrytan/gstack.

When a skill references `~/.kiro/skills/gstack/...` (legacy Kiro path), use
`~/.claude/skills/gstack/...` instead.

## Comments

Write comments for someone reading this file cold — not for a reviewer
following your change, and not as a record of how the code got here.

- Explain *why*, not *what*. Comment only what the code can't say itself: a
  non-obvious mechanism, a workaround and the constraint forcing it, an
  invariant, a gotcha. Don't narrate what the next line plainly does.
- Stay in-file. No comparisons to other modules ("unlike X", "matches Y",
  "same as Z"), no references to sibling files, no pointers to the discussion
  or PR that produced the code. If a reader would need the rest of the
  codebase or the change history to care, cut it.
- No meta-commentary. Drop "we now…", "this was changed to…", "NOTE:", and
  speculative asides about features that don't exist yet.
- Don't restate types or signatures in prose. Doc comments say what an export
  does, concisely, in the project's existing voice — skip "Details" padding
  that adds nothing non-obvious.
- Match the surrounding code: mirror the comment density, length, and idiom
  already in the file. When in doubt, write less.

Litmus test: if a comment only makes sense to someone who watched you write
it, delete or rewrite it.

## System Python

The system-wide `python3` (declared in nix-config, available on every host
after a rebuild) comes with a fixed set of packages. `~/.python-packages.md`
is generated by home-manager from the same list that builds that Python, so
it's always current — see it for the package list and how to handle one
that's missing. Check it before assuming a package needs installing,
vendoring, or a venv for a one-off script.

## Rust

New projects start on edition 2024, with `resolver = "3"` spelled out in virtual
workspace manifests. Never scaffold on 2021 — it has been superseded since Rust
1.85. Choose an older edition only for a stated reason, such as a dependency
that does not build on 2024, and say what that reason is.
